# 50M Latent-Reasoning LM — GIBC V2, Track 01

Two ~48M-parameter language models trained **from scratch** under the 50M cap:

- **plain** — a deep-thin dense transformer built from the current open-lab recipe (Qwen3 / Llama 3 / MobileLLM).
- **looped** — the same recipe with **recurrent depth**: a 4-layer core block is run `r` times per token. Same parameter budget, more compute per token, and `r` can be raised at test time so the model "thinks longer" without emitting more tokens.

## Architecture

| Component | Source | Why at 50M |
|---|---|---|
| 16k byte-level BPE, digits split individually, trained on our mix | Llama / Qwen digit splitting | A 151k vocab alone would be 77M params at d=512. Single-digit tokens make arithmetic learnable. |
| Tied input/output embedding | MobileLLM, SmolLM, Qwen3 ≤4B | Saves 8–10M params (≈20% of budget) at negligible quality cost. |
| Deep-thin shape (plain: 13 × d512) | MobileLLM | Depth beats width below ~125M params. |
| GQA (8 or 10 query heads, 2 KV heads) | Qwen, Llama 3 | Moves attention params into the FFN. |
| QK-Norm | Qwen3, OLMo 2, Gemma 3 | Bounded attention logits → stable at high LR on a single pass over the data. |
| SwiGLU, RMSNorm pre-norm, RoPE, no biases | Llama / Qwen / DeepSeek dense | Standard modern block. |
| Logit soft-cap 30 | Gemma 2, modded-nanogpt | Cheap protection against loss spikes. |
| Zero-init output projections | modded-nanogpt | Each block starts as identity. |
| Muon (matrices) + AdamW (embedding, norms), WSD schedule | Kimi/Moonlight, modded-nanogpt, MiniCPM | ~1.3–2× token efficiency over AdamW reported. |
| **Recurrent depth** (looped only): prelude 2 → core 4 × r → coda 2, input injection each loop, r ~ U{1..6} in training | Geiping et al. 2025 (Huginn), Saunshi et al. 2025 | Parameters store knowledge, loops add sequential computation. Under a parameter cap, extra compute is free capacity. |

**Considered and rejected:** Mixture-of-Experts (DeepSeekMoE) — the cap counts all experts, so each token sees a smaller network. MLA — saves KV cache for long-context inference, irrelevant at 2k context. Multi-token prediction — the extra heads count as trainable params, and it hurts models this small (Gloeckle et al. 2024). Mamba / RWKV / Gated DeltaNet — the benefit is long context; fast kernels are CUDA-only.

## Evaluation

- **Perplexity and bits-per-byte** on held-out FineWeb-Edu and TinyStories validation. BPB is tokenizer-independent, so it compares across submissions.
- **Zero-shot multiple choice** (log-likelihood, acc and length-normalised acc): ARC-Easy, ARC-Challenge, HellaSwag, PIQA, WinoGrande, OpenBookQA, SciQ, CommonsenseQA.
- **Arithmetic with worked steps**: 1,000 held-out problems, greedy decoding, exact match.
- Looped model evaluated at r ∈ {1, 2, 4, 6, 8, 12}.

## Reproduce

```bash
# 1. data + tokenizer (Kaggle CPU kernel, ~55 min)
kaggle kernels push -p kaggle/prep
# 2. training + eval (Kaggle TPU v5e-8 or GPU)
kaggle kernels push -p kaggle/run_plain_gpu --accelerator NvidiaL4
kaggle kernels push -p kaggle/run_looped --accelerator TpuV5E8
```

`kaggle/train/train.py` is the single trainer/evaluator (JAX). `MODE`, `TOKENS` and `ACC` (gradient accumulation) are environment variables. `SMOKE=1` runs a tiny CPU check.
